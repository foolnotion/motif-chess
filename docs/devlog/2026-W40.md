# Week 40 - 2026-10-02

## Decisions

- **[D051] Keep the current import pipeline configuration.** The release benchmark
  in `BENCHMARKS.md` measured the default 1,001,090-game path at 78.034 seconds,
  versus the comparable 81.520-second baseline. The desktop report came from a
  Debug (`-O0`) build over nested Wayland/waypipe, so it does not establish a
  pipeline regression or a safe algorithmic target.

## Learned

- The Slint desktop import path uses the production `import_config` defaults:
  exact-position postings rebuild enabled, opening-tree rebuild disabled,
  `hardware_concurrency() / 2` workers, and 500-game SQLite batches.
- Slint 1.18 deprecates the `ListView` `viewport-width`/`viewport-x` aliases
  and the `Flickable` `viewport-height` alias in favor of `content-width`,
  `content-x`, and `content-height`.

## Native scale/layout correction

- Removed the desktop entry point's hardcoded `set_size(1440, 860)` call. Slint
  now exposes logical minimum/preferred dimensions to the platform, allowing
  the native compositor to apply its own scale factor.
- Reduced the workspace logical constraints to 960×560 minimum and 1200×720
  preferred dimensions; the previous 1180×640 and 1440×860 constraints were
  oversized on the native 1.5-scale session.
- Centered replay controls in a style-sized toolbar row. Previously the
  vertically flexible control row expanded to the entire unused review-pane
  height, producing oversized and visually misaligned buttons.
- Native inspection after the change showed a centered setup form and compact
  36-pixel logical replay buttons. The 1.5 compositor scale remained reported
  by MCP; no physical-pixel conversion was added to application code.

## Responsive layout and keyboard focus (2026-10-03)

Compositor verification of Story 9.5 found notation unusable at the 960x560
minimum, `Open Game` clipped, and keyboard focus dropped after replay, board,
hide/show and notation actions. All are fixed in the `.slint` files.

### Learned

- Slint box layouts divide only the space left after each child's minimum by
  stretch factor. A review pane with minimum 0 beside a sidebar with minimum
  320px got about 40% of the row instead of two thirds, and a square board with
  a large stretch factor claimed width it could not draw, starving notation.
  `GameReviewPanel` now computes the board side from its own width and height
  and gives notation the remainder, with a declared minimum.
- A declared `min-width` on a layout hides, rather than removes, overflow from
  its children: the games footer needed more than the sidebar's 280px and
  clipped silently. Check the child minimums, not just the parent's.
- `preferred-width` computed from `root.width` on a layout child creates a
  binding loop through the window's own layout info; use minimums plus stretch.
- Replacing a model that feeds a repeater's count dirties the repeater even
  when the new count is equal, rebuilding every instance and dropping focus.
  `publish_board` replaces the move list on every navigation, so
  `NotationPanel` mirrors the count with an assignment in `changed san-moves`;
  assigning an unchanged value is silent.
- `interaction-enabled` flips on every auto-search that follows a navigation,
  so using it as the trigger for "take focus" pulled focus off whatever the
  user was operating. The host now bumps `board-load-serial` on activation
  success and the review region takes focus once per load.
- Slint 1.18 `ListView` scroll offset is `content-y`; `viewport-y` warns.

### Done

- Games footer split into counters/title and button rows; sidebar minimum 320px.
- Game table is one tab stop with a focus ring, Up/Down/PageUp/PageDown/Home/End
  and scroll-into-view; unselected Down starts at the first row.
- Hide/Show Board is one button; replay buttons no longer steal focus.
- Six regression tests in `layout_snapshot_test.cpp`: notation room at the
  minimum and at 1280x800 in both layouts, no right-edge clipping, replay
  button focus, hide/show focus, table keys, notation-move focus across a
  republished move list. The two focus tests were confirmed to fail when the
  old behavior was reintroduced.
